# Releasing

Docent ships two ways: prebuilt archives and an MSI on GitHub Releases, and the `docent` crate on crates.io. Both are cut from the same git tag.

## Version bump

The version appears in these places and they must agree:

- `Cargo.toml`, `package.version`.
- `plugins/firefox/manifest.json`, the extension version.
- `plugins/qutebrowser/docent_qutebrowser/__init__.py`, `__version__`.
- `plugins/zathura/docent_zathura/__init__.py`, `__version__`.
- The status line in `README.md`.

## Tag and release

Run the local checks, commit the bump, then push an annotated tag:

```bash
scripts/check.sh
cargo publish --dry-run
git tag vX.Y.Z
git push origin vX.Y.Z
```

The `Release` workflow (`release.yml`) is generated by cargo-dist and builds the archives for the five targets in `dist-workspace.toml`, the MSI, the checksums, and the GitHub Release. The `Publish` workflow (`publish.yml`) runs after `Release` succeeds and publishes the crate with `cargo publish --locked`.

Publishing is deliberately last: a version never appears on crates.io while the binaries for that tag failed to build. A tag whose version is already on crates.io is skipped, so re-running a release is harmless.

## crates.io

The first version of a crate cannot use trusted publishing, because crates.io only offers the trusted publisher configuration once the crate exists. The bootstrap is:

1. Publish by hand from the tagged commit:

   ```bash
   git checkout vX.Y.Z
   cargo login
   cargo publish --locked
   ```

2. On crates.io, open the crate's settings and add a trusted publisher for the GitHub repository `apanoush/docent`, workflow `publish.yml`, with no environment. This is a one-time step per crate.

Every later tag publishes through the `Publish` workflow, which exchanges a GitHub OIDC token for a short-lived API token using `rust-lang/crates-io-auth-action`. No long-lived token is stored in the repository. Trusted publishing is documented at <https://crates.io/docs/trusted-publishing>.

If the workflow is unavailable, the manual fallback is the same `cargo publish --locked` from the tagged commit.

## Permanence

A published version can never be overwritten or deleted, and a yank only hides it from new dependency resolution. Fix a bad release by publishing a new patch version, and use `cargo yank --version X.Y.Z` only to stop new installs of a broken one.

## Package contents

`cargo package --list` shows what ships. Two things to keep in mind:

- `src/viewer/page.rs` embeds `plugins/qutebrowser/docent_qutebrowser/answer.css` with `include_str!`, so that file has to stay in the package.
- The package also installs `docent-native-host`, the Firefox native messaging host, next to `docent` on `PATH`.
